# FlareMo 团队模式

## 定位

团队模式是 FlareMo 开源项目的基础能力，不是独立版本、付费能力或部署时需要选择的模式。

- 只有一个成员时，FlareMo 保持现有的个人使用体验。
- 管理员添加其他成员后，成员之间可以共享团队可见的笔记和附件。
- 所有开源用户都可以使用完整的团队能力。
- 第一版不引入组织、部门、群组、多团队、多租户、审批流、SSO 或 SCIM。

## 目标

完成一个最小、完整的团队协作闭环：

1. 团队管理员添加和管理成员。
2. 成员使用独立账号登录。
3. 成员可以创建仅自己可见、团队可见或全网公开的笔记。
4. 有效成员可以读取团队可见的笔记及其附件。
5. 团队管理员可以管理团队成员和团队内容，但不能读取成员的私密内容。
6. 成员被移出后不能继续访问 FlareMo；其私密和个人数据被删除，团队及公开内容继续保留。

## 非目标

第一版不实现：

- 组织、部门、群组或自定义角色；
- 多团队或跨团队协作；
- 资源级成员名单或复杂 ACL；
- 为团队模式新增开放注册、邮件验证或邮件邀请流程；
- SSO、SCIM、审批流或复杂审计；
- 团队项目、团队任务或共享 Agent Memory；
- 成员移出后的冻结期、内容交接或个人数据导出。

## 成员与角色

FlareMo 保留首次初始化的 `owner`，并增加可由管理员设置的 `admin` 角色：

- `owner`：首次初始化的团队管理员和技术恢复账号，不可被删除或降级；
- `admin`：团队管理员，可添加和移出成员、设置管理员、重置成员密码并管理团队及公开内容；
- `member`：普通团队成员。

成员状态为：

- `active`：可以登录和正常使用；
- `removed`：不能登录，不出现在正常成员列表中，但保留失效成员记录以显示历史作者。

约束：

- 团队中必须至少有一位有效管理员；
- 不允许移出或降级最后一位有效管理员；
- 被移出的成员不能通过 cookie session、PAT、MCP、脚本或兼容 API 继续访问；
- 邮箱只作为唯一登录标识，不发送或验证邮件。

## 团队管理

账户页面中的管理入口改名为“团队管理”，只提供：

- 查看有效成员；
- 添加成员；
- 设置或取消团队管理员；
- 移出成员；
- 为成员生成一次性密码重置链接。

添加成员时填写姓名、邮箱和初始密码。团队管理界面不提供开放注册入口，新增成员默认由团队管理员完成；为避免破坏已有部署，原有兼容接口的注册设置继续保留，并保持默认关闭。

## 笔记可见性

存储层继续使用 Memos 兼容值，产品界面显示为：

- `private`：仅自己可见；
- `protected`：团队可见；
- `public`：全网公开。

权限矩阵：

| 可见性 | 作者 | 其他有效成员 | 团队管理员 | 未登录访客 |
| --- | --- | --- | --- | --- |
| 仅自己可见 | 读、写、删除 | 不可见 | 不可见 | 不可见 |
| 团队可见 | 读、写、删除、修改可见性 | 只读 | 读、编辑、删除、修改可见性 | 不可见 |
| 全网公开 | 读、写、删除、修改可见性 | 只读 | 读、编辑、删除、下线 | 只读 |

所有有效成员都可以将自己的内容设为全网公开。前端切换到全网公开时必须二次确认“任何人均可访问”。

权限判断统一由 domain 层提供，Web、Memos-compatible API、MCP、附件、搜索、语义搜索和 SSE 不得维护相互独立的权限规则。

## 附件

- 已绑定到笔记的附件始终继承所属笔记的权限；
- 未绑定到笔记的附件仅上传者可见；
- 不能通过附件列表、附件详情、blob、文件兼容路径或分享路径绕过笔记权限。

## 搜索、语义搜索和事件

- 私密内容只能由作者搜索；
- 团队内容可以由所有有效成员搜索；
- 公开内容可以由未登录访客读取；
- Vectorize 只返回候选结果，最终结果必须回 D1 按当前成员和笔记状态过滤；
- SSE 不得向其他成员或管理员泄露私密笔记的名称、作者、事件类型等元数据。

## 移出成员

团队管理员移出成员时：

1. 立即将成员标记为 `removed` 并禁止继续访问；
2. 撤销该成员全部 session、PAT 和其他应用凭据；
3. 删除该成员所有仅自己可见的笔记及附件；
4. 删除对应的 R2 对象和 Vectorize 派生索引；
5. 删除该成员的个人项目、任务和 Agent Memory；
6. 保留该成员的团队可见和全网公开笔记及附件；
7. 保留历史作者名称；
8. 撤销该成员创建的随机分享链接。

移出操作必须可以安全重试。重复执行不能删除应保留的团队或公开内容。

## 升级迁移

- 现有 `owner` 保持 owner，并在界面中显示为团队管理员；
- 现有 `member` 保持普通成员；
- 所有现有成员状态初始化为 `active`；
- 为避免升级后意外共享，升级时将已有 `protected` 笔记改为 `private`；
- 已有 `public` 笔记保持公开；
- 升级完成后新设置的 `protected` 表示团队可见。

## 验收

至少使用 owner、admin、成员 A、成员 B 和未登录访客验证：

- 管理员可以添加成员和第二位管理员；
- 最后一位有效管理员不能被移出或降级；
- 默认部署未由兼容接口显式开启注册时，公开注册被拒绝；
- 成员 B 和管理员都不能读取成员 A 的私密笔记、附件、搜索结果或 SSE 事件；
- 成员 B 可以读取成员 A 的团队笔记及附件，但不能编辑；
- 管理员可以管理团队和公开内容；
- 未登录访客只能读取全网公开的笔记及附件；
- Web、Memos-compatible API、MCP、附件、全文搜索、语义搜索和 SSE 使用同一权限矩阵；
- 成员被移出后，旧 cookie、PAT 和 MCP 请求全部失效；
- 成员被移出后，其私密和个人数据被清理，团队及公开内容仍可正常访问；
- 旧 `protected` 数据升级后不会被自动共享。
